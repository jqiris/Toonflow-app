# 资产设定图提示词规范

> **视频提示词已切换到 H3 官方格式，图片规范独立。**

> **前提（必读）**：FreeVideo 官方指南只定义了 **五个视频任务**——`t2va`（文生视频）、`i2va`（图生视频）、`fl2va`（首尾帧视频）、`l2va`（末帧视频）、`ref2va`（参考生视频），**图片生成没有官方提示词规范**。因此本文件是 **Toonflow 自定规范**，不是 FreeVideo 官方标准，不得在文档、界面或回答里说成「官方要求」。
> 硬约束来源（实测代码）：`packages/providers/src/media/freevideo.ts:225-230`（模型 `freevideo-image` 的尺寸与比例）、`:246`（参考图上限）、`:69-80`（像素推导）。
> 字段与编号从哪来：[资产卡模板](assetCardTemplate.md)；参考接线怎么解析：[参考接线解析规则](referenceResolution.md)；生成流程：[逐分镜生成 SOP](generationRunbook.md)。
> 本文件**只讲提示词正文怎么写**；编号体系（`C` / `SC` / `P` / `KF`）、字段别名、参考声明一律以 [资产卡模板](assetCardTemplate.md) 为准，本文不重复定义。
> 设计维度（角色辨识 / 场景空间层次 / 道具材质状态）与出图验收清单见 [资产设计规范](assetDesign.md)；两份是分工不是副本：那份讲「这个资产该有什么」，本文件讲「这些内容怎么写成提示词」。

## 一、这是项目自定规范，别处没有官方版本可抄

| 判断 | 依据 | 后果 |
|---|---|---|
| 官方 tasks 只有 `t2va` / `i2va` / `fl2va` / `l2va` / `ref2va` | FreeVideo 官方指南实测 | 图片任务没有对应的官方任务名，也就没有官方段落结构 |

| 图片提示词无官方标准 | 同上 | 本文自定内容要素清单（§四），只列该说清什么，不规定段式；判断对错的标准是「能不能稳定产出一致的资产图」，不是「像不像官方」 |

边界（避免又造一份互相矛盾的副本）：

- `packages/skills/v118workflow/references/knowledge/imagePromptCraft.md` 的 Seedream 中文模板、Nanobanana/Gemini 结构化模板是**旧模型的写作模板**，该文件自己也声明不保证今天的模型仍支持同样的字段（`imagePromptCraft.md:7`）。**它们不是资产图的规范**，不要拿来写 `C` / `SC` / `P` 卡。
- 本文件管 `assetCard` 的资产设定图（角色/场景/道具/关键帧）。分镜首帧图走 `v118workflow` 的对应知识，画布直连片段走 [片段制作指南](../../canvas/references/videoProduction.md)。
- 图片规范只有这一处权威。要改规范改本文件，不要在其他技能里复写一份。

## 二、`freevideo-image` 硬约束（写提示词前先接受这些限制）

| 项 | 取值 | 说明 |
|---|---|---|
| 模型 | `freevideo-image`（`type: "image"`） | 本地 FreeVideo 引擎，本机 GPU，免计费 |
| 尺寸档位 | **只有 `1K`、`2K`** | 没有 4K/8K 档；`2K` 的 base 是 2048（`freevideo.ts:71`） |
| 比例 | **只有 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`** | 没有 `2:3`、`3:2`、`21:9`、`1.85:1` |
| 参考图上限 | **4 张**（Toonflow 侧限制，`freevideo.ts:250` 超限直接报错） | 引擎单块能到 9 张，但我们按 4 张写，不依赖未声明的余量。这个名额只数**图片**参考；图片模型根本没有音频/视频参考，不存在与音频卡混排占位的算法（视频镜的 `referenceIds` 是另一套口径：校验器 V8 允许图片 ≤9、音频 ≤1，但**多轨界面勾选上限只有 4**，见 [参考接线解析规则](referenceResolution.md) 末段 V8） |
| 生成模式 | `text`（文生图）、`singleImage`（单参考生图）、`multiReference`（多参考生图） | 三者都是「一段正文 + 可选参考图」，没有第三种提示词结构 |
| 负向参数 | **不存在** | 供应商请求只传 `prompt`；图片节点也没有 `negativePrompt` 字段。见 §七 |
| 输出 | PNG，单张 | 不做拼图、不返回多图 |
| 超时 | 单次 10 分钟 | 慢是常态，不要因为等不及就改小尺寸重跑 |

像素对应（长边 = base，短边按比例算，`freevideo.ts:74-78`）：

| 比例 | 1K | 2K | 资产用途 |
|---|---|---|---|
| `1:1` | 1024×1024 | 2048×2048 | 道具卡 `P`、方形构图卡 |
| `16:9` | 1024×576 | 2048×1152 | 场景卡 `SC`、四视图角色卡 `C` |
| `9:16` | 576×1024 | 1152×2048 | 关键帧/构图卡 `KF` |
| `4:3` | 1024×768 | 2048×1536 | 场景备选、道具特写 |
| `3:4` | 768×1024 | 1536×2048 | 道具竖幅、竖构图备选（角色卡不用，角色卡固定 `16:9`） |

硬约束带来的写作纪律：

1. **四视图必须在一张图里**。模型不返回多图，所以「半身像/正面全身/侧面/背面」是一次生成的四个栏目，不是四次生成再拼。正文要写清栏目顺序与对齐方式（§五·5.1）。角色卡**只有四视图整版一种版面**，不存在单视图、三视图变体。
2. **不要在正文里许愿模型没有的能力**：不写「8K 超清」「3:2 横幅」「输出四张图」「参考图 8 张」。
3. **比例写不对等于白写**。正文里写的画幅只是给模型的构图暗示，真正落盘的是节点上的 `ratio` 参数；两者必须一致，不能正文写「竖构图 2:3」而参数给 `1:1`。

## 三、与资产卡字段的对应（本文不定义字段）

| 资产卡里的东西 | 在哪定义 | 本文负责什么 |
|---|---|---|
| 编号 `C` / `SC` / `P` / `KF`、状态后缀 `C01-A`、编号唯一与规范化 | [资产卡模板](assetCardTemplate.md) §一、[参考接线解析规则](referenceResolution.md) §1.1 | 不重复。正文里可以点编号（「同一张脸·C01」），但编号的合法性由模板与校验器管 |
| `提示词` / `人物提示词` / `场景提示词` / `道具提示词` 等别名 | [资产卡模板](assetCardTemplate.md) §三 | 字段里的**正文**按本文 §四～§七 写 |
| `建议画幅` | [资产卡模板](assetCardTemplate.md) §二、§三 | 按下方回落表落成 `freevideo-image` 的合法比例 |
| `身份参考` / `结构参考` / `道具参考` / `参考派生` | [资产卡模板](assetCardTemplate.md) §三、[参考接线解析规则](referenceResolution.md) §二 | 正文要写清「参考被用来保留什么」，且参考张数 ≤4 |
| `负面提示词` / `统一排除项` | [资产卡模板](assetCardTemplate.md) §三、§四 | 是**写作字段**，投喂时并进正文（§七），不是 API 参数 |
| `文本类` / `仅文字记录` | [资产卡模板](assetCardTemplate.md) §三 | 置位的卡不出图，本文不适用 |
| 画幅三档搜索（单卡 > 节标题 > 前缀默认） | [资产卡模板](assetCardTemplate.md) §一 | 解析出前缀默认值后，**必须再过一次下面的回落表** |

画幅回落表（模板默认值 → 模型合法值）：

| 卡类型 | 模板默认画幅 | 实际下发 | 理由 |
|---|---|---|---|
| `C` 角色 | `16:9` | **`16:9`**（2048×1152），固定四视图整版 | 角色卡**只有四视图整版一种版面**：需要某个角度就重出一版四视图，不切成单视图；四栏在 `1K` 下每栏约 256px 太窄，必须用 `2K`，不许用「换成单视图」来省尺寸。旧模板默认写 `2:3`（不在五种比例里），模板已改为 `16:9`，仍写 `2:3` 的旧卡按本行回落 |
| `SC` 场景 | `16:9` | **`16:9`** + `2K` | 直接可用 |
| `P` 道具 | `1:1` | **`1:1`** + `2K` | 直接可用；需要展示厚度时用 `4:3` |
| `KF` 构图卡 | `9:16` | **`9:16`** + `2K` | 直接可用 |

- 卡片里写 `建议画幅：2:3` 属**历史写法**（旧模板的默认值）：解析器仍接受并按上表回落，但新卡一律写 `16:9`，不要靠回落写卡，更不要为了省尺寸退回单视图/三视图。
- 回落是单向的：合法比例不得被改写成模板默认值再回落一遍，否则同一张卡两次生成会得到不同比例。

## 四、正文该说清什么（内容要素清单，不是格式）

FreeVideo 没有图片任务，也没有图片的段式定义；本项目同样不规定图片提示词的格式。本节只列**一段图片提示词该说清哪些内容**：顺序、分段、是否空行都不限，五个要素连写成一段也可以。判断标准是「要素齐不齐、锚点是否逐字复用」，不是「段数对不对」。同一批资产图沿用同一套要素，跨集才不会各写各的。

| # | 要素 | 说清什么 | 别写什么 |
|---|---|---|---|
| 1 | **主体与版面** | 这是什么资产、几张视图、怎么排、占画幅多少 | 剧情、情绪、镜头运动 |
| 2 | **形貌锚点** | 从 §六 逐字复制的锚点短语 | 形容词堆砌（「绝美」「惊艳」） |
| 3 | **状态与视角** | 本次状态（新/旧/伤/雨/夜）、视角与朝向 | 会覆盖锚点的改写（「换个发型」） |
| 4 | **背景与光** | 背景（纯白/中性灰/空间）、光（均匀柔光/固定时段）、留白与接地影 | 「电影感」「8K」「大师作品」这类不改变构图的空话 |
| 5 | **排除项** | §七 的负向词，写进正文最后一句 | 任何参数名（`negative_prompt`、`--no`、`cfg`） |

参考写法（按要素顺序写成一段，可分段也可连写；替换 `【】`）：

```text
【资产类型】设定图。【视图版面：横向四栏 / 单张静物 / 空间空镜】，【占画幅比例与留白】。

【外貌/形制/空间锚点，逐字复制】：……

【本次状态】：……；【视角与朝向】：……。

【背景与光】：……；【材质与清晰度要求】：……。

排除：字幕、水印、界面元素、多余人物、多手多指、畸形、网格线、拼接痕迹。
```

- **正文用中文写**。图片没有官方语言要求，资产卡、剧本、卡片全是中文，中文正文让写作者和审阅者能逐字核对锚点；不要因为视频六段默认英文就跟着写英文，也不要中英各写一遍（两份描述必然分叉）。
- 一段只干一件事。把「四视图版面」和「面部毛孔要看清」揉进同一句，模型会只做其中一件。
- **上面只是参考排法，不是格式门槛**：连写成一段、换要素顺序、加不加小标题都不算错；只有要素缺失（尤其锚点和排除项）才算错。视频的六段/三段只属于多轨路径，不套到图片上（§一）。

## 五、三类模板（可直接套用）

### 5.1 角色设定图 `C`

规格：比例 `16:9`、尺寸 `2K`（四栏各约 512×1152）。**固定一版四视图**，**一张图四个栏目**：从左到右为 ①**半身像**（正面、腰部以上，面部结构清晰可辨）→ ②**正面全身** → ③90° 侧面全身 → ④背面全身。

对齐方式（必须写进正文，否则模型会把半身像也拉成全身）：

- **半身像栏**：单独构图——头顶贴齐栏顶、画面裁到腰（只显示头到腰），人物按上半身比例放大；面部结构由这一栏承担（脸型、五官、发际线、疤痕位置都在这里看清）。它与三个全身栏**不共用比例尺**，不要按肩线或脚底线去对齐别人。
- **三个全身栏（正面 / 90° 侧面 / 背面）**：按**脚底线**对齐，三栏共用同一全身比例尺、同一身高，头顶自然等高；鞋、下摆、裤/裙的正面形制靠正面全身栏核对。
- 只有三个全身栏之间才比较比例；半身像头部明显大于全身栏头部，这个大小差就是景别差。**禁止把半身像拉成全身**，也禁止用统一身高去画四栏。

- 四栏挤到互相粘连（引擎把相邻两栏画成一个人）时，唯一允许的备选是 `1:1` 的 2×2 四宫格（每格 1024×1024，顺序为左上**半身像** / 右上**正面全身** / 左下侧面 / 右下背面）。仍然是**一张图**，不许拆成四次生成，也不许改成单视图。

```text
角色设定图，四视图版面：横向等分四栏，栏间留白；从左到右依次为半身像、正面全身、90° 侧面全身、背面全身。四栏同一人物、同一服装；半身像为正面、头顶贴齐栏顶、画面裁到腰、面部结构清晰可辨、人物按上半身放大；正面、侧面、背面三栏共用同一全身比例尺、按脚底线对齐、头顶自然等高。

外貌锚点：圆脸，单眼皮，左眉尾一道浅疤，黑发束顶髻，肤色偏冷白，身形清瘦偏高。
服装锚点：月白交领长衫，袖口半尺宽，腰束深青布带，足下黑布靴。

状态：衣袍干净无破损，神情平静；四栏均为平视、人物直立，三个全身栏双手自然垂放于体侧并完整可见，鞋与下摆完整入画。

背景：纯白背景，均匀柔光，人物脚下极淡接地影，无环境道具；版面无手部特写、无文字、无水印、无网格线。

排除：文字、字幕、水印、标签、网格线、分栏边框、拼接痕迹、多余人物、多余的手、多指、畸形、面部扭曲。
```

- **「无手」的口径**：角色卡里指**不另加手部特写**、不出现多余的手或脱离身体的断手，**不是**把人物画成没有手——三个全身栏必须画出自然垂放的完整双手，否则这张卡接进视频就是残肢。
- 文生图（首张）与参考生图（派生）的差别只在开头一句：
  - 首张：`角色设定图，四视图版面：……`（如上）
  - 派生：`以参考图 1 为同一人物的身份锚点，重绘同一角色的四视图版面：……面部结构、发际线、疤痕位置与参考图 1 及半身像栏完全一致，仅更换服装为【新服装锚点】。`
- 参考图只用**1 张**（该角色的基卡）。要同时锁「脸」和「服装」时才用 2 张并写清各锁什么；凑满 4 张不会更准，只会让模型在四个来源间折中。
- 一张卡只放**一个**角色。两个角色放同一张四视图，模型会把两套五官混成一张脸。

### 5.2 场景设定图 `SC`

规格：比例 `16:9`、尺寸 `2K`；**空镜、无人物**（场景固有的人物痕迹可以有：翻开的书、未收的碗，但不出现人）。

```text
古风庭院场景设定图，空镜，画面内无人物、无动物、无手。

空间锚点：正屋三开间，青砖地面，东墙一扇方格木窗，窗外一株古槐，梁下悬一盏白瓷灯。
空间层次：前景为石阶与落花，中景为庭院与古槐，背景为正屋立面与远墙，纵深由近及远逐层收窄。

固定光照时段：午后斜阳，光自画面左前方射入，窗棂投影落在青砖地上，阴影清晰、色温偏暖。

背景与光：写实电影质感，广角平视，主体居中，画面上方留出屋檐与天空；材质清晰，木纹与砖缝可辨。

排除：人物、人影、手、字幕、文字、水印、界面元素、网格线、拼接痕迹、畸形结构、透视错乱。
```

- **一个时段一张卡**。`SC01-A`（午后）与 `SC01-B`（雨夜）是两张卡，空间锚点逐字相同、只换光照段与状态段。不要在一张卡里写「晨昏皆可」——模型会挑一个你不可控的时段。
- **层次必须写三层**（前景/中景/背景）并说明遮挡关系。视频里人物要走进这个空间，深度含糊会让每段的分寸都不一样。
- 固定光照时段要写成**可执行的物理描述**（光源方向、色温、投影落点），不写「氛围神秘」「光线优美」。
- 场景卡不要写「有个人站在树下」；人只有在分镜格里出现（[资产卡模板](assetCardTemplate.md) §六 角色分离）。
- **同场景跨镜多角度**：先生成全景图，再截取对应角度的场景图作该镜参考，不逐角度独立重画。链路：基础场景卡节点 `node:createPanorama({ mode })`（sphere 720° / cylinder 360°）→ `node:generateImage` 出全景图 → `node:capturePanorama({ count, layout })` 按机位截取并自动建角度图节点连线。注意 freevideo-image 合法比例只有 1:1 / 16:9 / 9:16 / 4:3 / 3:4，而全景链路内部用 2:1（sphere）/ 4:1（cylinder），该供应商下可能失败——失败时降级 `node:generateMultiAngle` 预设机位（front/back/left/right/high/low 等）或导演台导出关键帧作角度参考。角度图逐字沿用基卡的空间锚点与固定光照时段，是本集中间件、不入 assetCards.md。

### 5.3 道具设定图 `P`

规格：比例 `1:1`（要展示厚度用 `4:3`）、尺寸 `2K`；**单件静物、白底、无手、无人**。

```text
道具设定图，单件静物，画面内只有这一件器物，无人、无手。

形制锚点：榆木八仙桌，桌面正方，四腿直落，牙板素面无雕花，桌面厚一寸。
尺度参照：桌面 90cm×90cm，桌高 80cm；对照物为右侧一只标准 30cm 高的木凳。
材质与状态：榆木纹理清晰，边角磨圆，桌面有常年擦拭的油亮包浆，右前腿有一处磕碰缺口。

视角：正面微俯 15°，能同时看到桌面与桌腿结构；器物居中，占画幅约 70%。
背景：纯白背景，均匀柔光，器物下方极淡接地影。

排除：人物、手、字幕、文字、水印、界面元素、网格线、拼接痕迹、多余物件、畸形结构、多腿多面。
```

- **尺度参照是硬要求**。没有参照，同一件「剑」在不同集里会变成短匕或长枪。可用具体尺寸（`长约 90cm`）或身旁的已知参照物（`与成年男性小臂等长`）。
- **材质 + 状态分开写**：材质是锚点（永远榆木、永远黄铜），状态是可变的（新/旧/破损）。状态变异成 `P01-B` 时只改状态段。
- 不要写「握在手中」「被人举起」——那是分镜格的事，放进道具卡会把人家手带进母版。

## 六、一致性锚点：写法与跨集复用

锚点是**逐字复用**的短句，不是形容词集合。作用：让同一角色/空间/器物在几十张卡里长得一样。

### 6.1 三组可复用短语

| 类型 | 可复用短语（示例，按此颗粒度写） | 写几条 |
|---|---|---|
| **外貌锚点** | `圆脸，单眼皮，左眉尾一道浅疤，黑发束顶髻，肤色偏冷白，身形清瘦偏高` | 4–6 |
| **服装锚点** | `月白交领长衫，袖口半尺宽，腰束深青布带，足下黑布靴` | 3–5 |
| **空间锚点** | `正屋三开间，青砖地面，东墙一扇方格木窗，窗外一株古槐，梁下悬一盏白瓷灯` | 4–6 |

写法规则：

1. **具体到能画**：`单眼皮` 能画，`眼神深邃` 不能；`左眉尾一道浅疤` 能画，`气质清冷` 不能。
2. **按 形 → 色 → 质感 → 特征 排序**，模型对位置靠前的词权重更高。
3. **不写情绪、剧情、关系**。锚点描述「他长什么样」，不描述「他在生气」或「他和谁对立」。
4. **不写镜头词**。`特写`、`俯拍` 属于状态段与版面段，混进锚点会让每张卡都被迫用同一景别。
5. **锚点句逐字复制**，不改标点、不换同义词。`清瘦` 改成 `偏瘦` 就已经是另一个锚点了。

### 6.2 跨集复用：只改状态，不改锚点

| 允许改 | 不允许改 |
|---|---|
| 状态段：伤势、衣袍新旧、淋湿、血污、时段、天气 | 外貌锚点里的任何一项（脸型、眼型、疤痕位置、发式、肤色、身形） |
| 视角与朝向、景别、构图版面 | 服装锚点的形制与主色（换整套衣服要新建服装锚点句，并说明是"新服装"） |
| 排除项（按本次风险增删） | 空间锚点的结构项（开间数、门窗位置、主要陈设位置） |

- 写法上把状态写在锚点**之后**，并显式声明锚点不动：`外貌锚点与服装锚点同上，仅状态改为左颊一道血痕、衣袍破损`。
- 状态后缀卡（`C01-A` / `P01-B` / `SC01-B`）走的正是这条路：复用基卡锚点，只换状态段；身份参考仍指基卡。
- **锚点一变就是新卡**。确实要改脸、改服装形制、改空间结构，新建一张卡并换编号，不要在旧卡上原地改字——旧卡生成的图不会跟着变，工作区里就出现两套「同一编号、不同长相」的资产。
- 跨集复用时的核对口径：把基卡锚点句与派生卡锚点句做**逐字比对**，不一致就退回重写，不接受「意思一样」。

## 七、负向词：写进正文，不发明参数

### 7.1 词表

| 类别 | 词 | 主要用在 |
|---|---|---|
| 字幕与文字 | 字幕、文字、标签、标题、说明文字、任何可读字符 | 全部三类 |
| 水印与标识 | 水印、Logo、签名、版权字样、`AI generated` 角标 | 全部三类 |
| UI 覆盖 | 界面元素、按钮、进度条、边框、分栏线、时间码 | 全部三类 |
| 多余人物 | 人物、人影、路人、观众（`SC` / `P` 必写；`C` 写「多余人物」） | `SC`、`P`、`C` |
| 手部 | 多余的手、第三只手、断手、多指、六指、手指粘连 | `P`、`SC`；`C` 写「多余的手、多指」 |
| 畸形 | 畸形、肢体扭曲、面部扭曲、五官错位、多腿多面 | 全部三类 |
| 网格线 | 网格线、参考线、坐标格、九宫格线、分栏边框 | 全部三类（四视图尤其危险） |
| 拼接痕迹 | 拼接痕迹、接缝、色块断裂、重复纹理、画面撕裂 | 全部三类 |

按卡类型的最小集（没把握就用这一行，别自己删项）：

- `C`：文字、字幕、水印、标签、网格线、分栏边框、拼接痕迹、多余人物、多余的手、多指、畸形、面部扭曲。
- `SC`：人物、人影、手、字幕、文字、水印、界面元素、网格线、拼接痕迹、畸形结构、透视错乱。
- `P`：人物、手、字幕、文字、水印、界面元素、网格线、拼接痕迹、多余物件、畸形结构。

### 7.2 只有一条 `prompt` 字符串时怎么给负向

**事实**：`freevideo-image` 的请求里只有一个提示词字符串。`packages/providers/src/media/freevideo.ts` 的 `generateImage` 只读 `request.prompt`（`:249-257`），供应商与图片节点全链路都没有 `negativePrompt` / `negative_prompt` 字段。

所以：

1. **把排除项写进正文最后一句**，以 `排除：` 起头，与画面描述同段或独立成段都行，但必须在同一个字符串里。
2. **资产卡里的 `负面提示词` / `统一排除项` 是写作字段**（[资产卡模板](assetCardTemplate.md) §三、§四），投喂时并成正文一句（`排除：文字、水印、畸形手指`），**不要**当作独立参数下发，也不要新增「负向提示词」API 字段。
3. **不发明参数**：不写 `negative_prompt`、`--no`、`no_glyph`、`cfg_scale`、`sampler` 这类模型没有的键；不在正文里写 JSON 参数块。
4. **正向覆盖优先**：模型对「要什么」比对「不要什么」更敏感。写 `排除：文字` 的同时，正文里要有「画面内不含任何可读字符」这类正向表述；只堆「不要」会得到一张布满文字但被你反复否定的图。
5. **8–12 项封顶**。超过就只留与本次风险相关的项（例如四视图留网格线与拼接痕迹，静物留多余物件与手）。

## 八、出图前自检（十项，逐条打勾）

1. 比例在 `1:1 / 16:9 / 9:16 / 4:3 / 3:4` 之内，且与节点参数一致；
2. 尺寸只写 `1K` 或 `2K`，没有 4K/8K；
3. 参考图 ≤4 张，且每张都写清被用来保留什么；
4. `C` 卡四视图齐全（**半身像**/正面全身/侧面/背面），第一栏是半身像；半身像头顶贴齐栏顶、裁到腰、单独放大，三个全身栏共用同一全身比例尺、按脚底线对齐；比例 `16:9` + `2K`；
5. 背景是纯白或中性纯色，无环境杂物；
6. 锚点句与基卡逐字一致，状态写在锚点之后；
7. `SC` 卡无人物、无手、无动物；
8. `P` 卡单件、带尺度参照、材质与状态分开写；
9. 排除项覆盖：字幕、水印、UI 覆盖、多余人物、多手多指、畸形、网格线、拼接痕迹；
10. 正文里没有任何参数名、英文六段标签或 JSON。

十条里有任何一条不满足，先改提示词再点生成；不要用多跑几次的方式碰运气，那只会让同一张卡产生多个互相不一致的版本。

## 九、常见错误

| 错误写法 | 后果 | 正确做法 |
|---|---|---|
| 把视频 ref2va 六段套到图片上 | 出现「overall_soundscape」等空段，模型忽略半篇内容 | 按 §四 的要素清单补齐内容，不套视频段式 |
| 四视图写成四次生成 | 每张脸都不一样，四张图无法当同一角色 | 一张图四栏，正文写死栏位与比例尺 |
| 想「只出单视图/三视图省事」 | 模型没有这套版面，切出来的图既不能锁脸也不能接视频 | 角色卡只有四视图整版；要某个角度就重出一版四视图；`1K` 四栏太窄就用 `2K`，不是退回单视图 |
| 半身像栏被拉成全身、四栏比例混乱 | 脸被压扁，裤/裙/靴的正面形制与身体比例无法核对 | 半身像头顶贴齐栏顶、只画到腰、单独放大；正面/侧面/背面三栏共用全身比例尺、按脚底线对齐 |
| `建议画幅：2:3` 原样下发 | 供应商不接受该比例，或退回 `1:1` 得到方图、四栏全挤在一起 | 按 §三 回落：角色卡固定 `16:9` + `2K` |
| 场景图里写「树下站着一个少年」 | 场景卡带人，接进视频后每段都多一个人 | 空镜；人只在分镜格出现 |
| 道具卡写「握在手中」 | 母版把手带进来，后续每张道具图都有手 | 单件静物、白底、无手 |
| 每张卡重写锚点 | 同角色跨集长相漂移，且无法定位是哪次改坏的 | 锚点逐字复制，只改状态段 |
| 写 `negative_prompt: [...]` | 参数不存在，被引擎当正文或直接丢弃 | 排除项并进正文（§七·7.2） |
| 参考图塞满 4 张 | 模型在多个来源间折中，脸更不像 | 首张 1 张基卡；确需锁两件事时才用 2 张 |
| 用 `v118workflow` 的 Seedream/Nanobanana 模板写资产卡 | 模板字段与当前模型不对应，负向段落落空 | 本文件是资产图唯一规范 |
