# 3D 预演（导演台）

可选环节：分镜表确认之后、正式分镜图产出之前，用导演台节点把复杂场景先搭成 3D 低模、定好机位与运镜，导出关键帧图片和运镜预演视频，作为分镜图与视频生成阶段的参考输入。复杂的转场或动作（转场设计、多人动作调度、连续运镜、连续多机位）应先在这里预演定好机位、动线与动作轨迹才值得搭 3D 场景，避免视频生成直接反复抽卡的代价。同一场景仅换角度、无复杂走位时优先走全景派生路径（见 [跨镜一致性](sceneConsistency.md)）；简单正反打、单镜头场景可以不进本环节。跳过须用户确认并在阶段记录写明未预演的镜头范围。

## 节点与能力发现

1. 本环节在当前集画布内进行，先按 `canvasOperations.md` 核对画布 ID 与节点落位。
2. `getCanvas({ include: ["nodeTypes"] })` 确认 `remote-director3dNode` 在 `availableNodeTypes` 中，用 `addNode` 创建导演台节点并登记 ID。类型不存在说明插件未启用：请用户在插件市场启用「导演台」后继续，不手写画布 JSON、不假装有该节点。
3. `getNodeTools({ nodeIds: [导演台节点ID] })` 读取本节点真实函数与 schema，以下命令均以回执为准；函数缺失时如实报告缺项。

## 输入准备

- 参考图与剧本文本连到导演台 `in` 口（STRING/IMAGE/VIDEO 均进引用序列），用 `getCanvasNodes` 回读引用就绪情况；未就绪引用会占位并阻止生成，先补内容再生成。
- `node:getConfig` 查看当前模型与配置。搭建场景走多轮工具调用循环，模型必须支持工具调用；带图片引用时必须选支持视觉的多模态模型。`node:setConfig` 成对传 `providerId` 与 `modelId`，变更后再次 `getConfig` 核对。

## 搭建与迭代

1. `node:generateScene({ instruction })` 发起后台生成，指令一次讲清：场景结构与布局、角色站位、动作、镜头需求。首次创建场景时同一节点只允许一个生成任务；已有场景后不同指令可并行，各自形成独立镜头方案。
2. 用本节点 `node:getGenerationStatus` 轮询（`idle/running/succeeded/failed`），取消用 `node:cancelGeneration`。`failed` 读取 `error` 原样报告；回执「Agent 未修改方案」时缩小或明确指令后重试，不原样重复发起。
3. `node:getState` 审查场景对象、机位锚点与镜头方案（名称、时长、轨迹数），`node:selectPlan` 选定待导出方案。空间关系、走位或运镜需要修正时，继续用 `generateScene` 以自然语言修改现有场景，再回读状态验证。
4. 预演内容必须来自已确认的分镜表镜头范围：不新增剧情、不改人物设定、不擅自扩写动作。

## 导出到画布

- `node:exportKeyframe` 导出机位关键帧 PNG 到图片节点，供分镜图阶段做构图与站位参考；`node:exportVideo` 导出方案预演 MP4 到视频节点，供视频阶段做运镜与节奏参考。两者自动启用所需的图片/视频节点插件。
- 单次导出受约 240 秒与约 100 MB 上限约束（实际上限随码率变化），超限会被拒绝：按方案拆短或逐机位导出关键帧，不硬重试。
- 导出在页面内实时录制：桌面客户端会自动唤起并置前主窗口，浏览器环境需用户保持该页可见且前台，发起前告知用户不要切换窗口。
- 记录导出得到的节点 ID 与文件路径，回读节点输出验证媒体真实存在后才算产出。

## 产出与回写

1. 在分镜表同一集画布增加本阶段记录节点，写明：参与镜头、导演台节点 ID、使用的方案 ID、导出成果（节点 ID 与路径）、模型配置。
2. 预演成果是参考素材，不是正式分镜图或成片；分镜图（步骤 12）与视频（步骤 13）的确认关口不得因预演存在而跳过。用户明确要求采用预演成果交付时才按交付记录。
3. 完成、部分完成或跳过都记录真实状态与原因，回读节点后汇报；状态未查询成功前不得声称预演完成。
