# 12 验收、合成与交付

## 1 结果回读与归属确认

用户报告完成（或本轮有真实查询/等待能力）后：`planOperator mtrackRead` / `node:readClips` 读目标镜 `status`、`assetPath`、`attempts`、`qc`。核对：产物文件真实存在可读；输出归属本次授权方案——用户在等待期间可能手动生成或替换过素材，归属不清先问"这次输出对应哪次生成"，不自动归因、不下游采用。

## 2 画面验收（提示词审计≠看片）

真实视频是否多手多指、肢体融合、变脸、道具闪现消失、穿模、镜像错误**必须看片判定**；视频路径存在不代表 agent 看过视频。核验手段：批次勾"生成后自动质检"看每镜 `qc`（pass/fail/unknown+note，只标记不自动重拍——VLM 是模糊信号，静默重 roll 会误判白烧 GPU）；或 `mediaGeneration askVlm` 按三问抽查（主体一致性/字幕水印/画面崩坏）；界面「审片」等价。**未过的镜头汇报 `qc.verdict==="fail"` 清单与原因，建议重拍或调提示词，由人决定**；读 qc 用默认版本那条记录，不自己 `findLast(succeeded)` 定位（takes 多候选会命中错版本）。能力读不了视频时：用户预览，agent 记录问题、交界状态与采用决定，明确标注未核验部分。

## 3 验收与合成

1. 用户逐个看片，多轨界面逐镜点「验收」→ `accepted`。清单：身份不漂/服装连续/空间结构一致/动作在时长内完成/台词说完不吞字/无字幕水印/首尾可接。打回→改后回 pending 重派（核对授权变化）或版本菜单切回旧版（版本操作，不是先别落盘）。
2. `planOperator composite execute:false` 先看清单（只含 accepted、clipId 顺序连续无空洞 V14；规格不一致 execute 前被 ffprobe 挡下）。
3. `execute:true` 出片。缺片失败片长度不足→停在对应镜头，**不用黑帧、循环、加速或其他镜头偷偷补齐**。「没有 accepted 片段可合成」如实转告差哪几镜。
4. 配乐可选：`mediaGeneration music`（caption 必须英文、先读最新 revision）。`editorProjectId` 是 **FreeVideo 引擎侧的编辑工程号**（形如 `e-`+32 位十六进制；从引擎 `/projects` 列表取，多来自用户在引擎里新建的空工程——**为本用途准备一个专用配乐工程**：provider 传 `sourceVideo` 时会先清 v1 轨再导入成片对齐长度，复用主成片工程会替换其视频轨并堆积素材；只传纯配乐请求则不触碰 v1）。时间线须 10–600s；失败不阻断合成，可不带配乐直接合成。
5. 通过判据：`composite.json` `executed=true` 且有成片路径。

## 4 交付口径（四类分清，不混称）

| 口径 | 含义 |
|---|---|
| 已生成片段 | `generated`：磁盘有产物、工程有版本，未验收 |
| 用户采用片段 | `accepted` |
| 已合成成片 | composite executed 的产物 |
| 已归集副本 | 复制交付目录的拷贝 |

没有对应能力就交付现有成果+缺项清单，**不宣称成片**；"已授权/目录可读/构建通过"都不等于出片。交付汇总登记：各镜状态、实际规格（画幅/分辨率/实测时长）、剩余问题、下一步路线。已采用素材优先固定在素材节点，修订另建候选。

## 5 断点恢复

新会话/上下文压缩后续接顺序：`filmProject/projectStatus.md` + `routing.md` → 有工程 `mtrackRead` 读实际进度 → 从首个未过门禁的阶段/镜继续；重新读取所需原件（见 overview.md 第 7 节），不把旧"读过"标记当永久记忆。

## 6 诚实底线（全流程通用，违反即失败）

- 不伪造：读图、看片、锁定、版本、验收、知识库命中、返图、生成成功；不能凭路径声称看过。
- 保存失败、能力缺失、未核验范围，立即如实说明；写入失败不得报告已保存。
- 工具返回不明确时不盲重试（防重复烧算力）；方案变化重新核对授权。
- 不要求作者重复批准已确认的同一事实；但作者的新决定只登记不揣测。
- 阶段名相同或文件已创建≠产出一致；生成任务启动≠媒体成功；两次 AI 生成不承诺逐字/逐帧相同。
