# 项目结构与治理（每轮必读）

## 1 工作区布局（Toonflow 项目适配）

所有路径为工作区相对路径（经 `useWorkspaceFiles` / 工具接口读写），`/` 分隔，目录与文件名小驼峰：

```text
<项目工作区>/
├─ filmProject/
│  ├─ projectStatus.md          # 项目状态总卡（下方 §2）
│  ├─ routing.md                # 路由与回退历史
│  ├─ concept/       synopsis-vNNN.md
│  ├─ characters/    characters-vNNN.md
│  ├─ worldbuilding/ worldbuilding-vNNN.md
│  ├─ treatment/     treatment-vNNN.md
│  ├─ screenplay/    screenplay-vNNN.md ｜ timingAudit-vNNN.md ｜ productionBreakdown-vNNN.md（B 入口）｜ novelAdaptationAudit-vNNN.md（小说改编）
│  ├─ stressTest/    report-vNNN.md
│  ├─ acting/        <场次>-acting-vNNN.md
│  ├─ shots/         <场次>/（shotPlan-vNNN.md ｜ generationUnits-vNNN.md ｜ sceneSpaceMap-vNNN.md ｜ continuityLedger-vNNN.md ｜ referenceMap-vNNN.md ｜ visualAudit-vNNN.md ｜ sceneRegistry.md）
│  ├─ prompts/       <场次>/h3-vNNN.md
│  ├─ assets-vNNN.md             # 07 资产状态登记（可读契约；机器真源在 assets/assetCards.md）
│  ├─ screenplayIntakeReport-vNNN.md（B 入口接管检查报告，同样独立取号）
│  ├─ knowledge/     <阶段>-profile.json ｜ <阶段>-candidates.md（13 册检索工件）
│  ├─ referenceMemory.md         # 已确认参考方法（跨会话唯一事实源）
│  ├─ enhancements/enhancementMemory.md  # 已挂载增强分支（14 册）
│  └─ knowledgeBase.json         # 本地知识库配置（脚本读这份）
├─ assets/assetCards.md          # 资产卡主记录（07 产出，多轨真源之一）
├─ plan/story.mtrack             # 多轨工程（唯一工程真源）
└─ plan/assetIndex.json          # 卡号→图片节点索引（工具生成，不手写）
```

旧项目已有其他目录布局的沿用原布局工作，先探测再写，不在旧项目旁另起一套；`filmProject/` 只用于新建项目。原稿（小说、作者剧本）留在原位或用户指定路径，登记时引用原文件名。

## 1.5 每轮开工统一三步（直达任何分册都先执行）

1. 读 `filmProject/projectStatus.md`（恢复现场）与 `routing.md`（路由与回退历史；缺失时按 projectStatus 与工程实况恢复，不阻断）。
2. 读 `filmProject/referenceMemory.md` 中**使用范围覆盖当前阶段**的启用方法（13 册），有则沿用不重检索；读 `filmProject/enhancements/enhancementMemory.md` 中当前阶段/场次已挂载分支（14 册），未挂载不加载正文。
3. 视频制作意图命中 SKILL「路由锁存」时先锁 H3 执行态。

## 2 projectStatus.md（一卡恢复现场）

每轮开工先读它，收尾前更新它：

```markdown
# 项目状态 · <项目名>
- 入口：A/B/C/D/E ｜ 定位：01 的 A–E ｜ 合作档位：新手/进阶/高手
- 口径锁：目标时长 ｜ 语种 ｜ 类型 ｜ 主角一句话 ｜ 受众 ｜ 发布目标（影展/短视频/长剧/付费短剧）
- 当前阶段与状态：05 screenplay v003 已确认-当前 …（逐道列）
- 06 处置：采纳=是/否/部分 ｜ 授权=按病灶（…除外） ｜ 计数器：06重审 ×N；04+缺关键事件 ×N
- 09 档位：快速出片/一起打磨/自由掌镜 ｜ 模型：MiniMax-H3（providerId/modelId）
- 生成授权记录：本次对象、数量、方案摘要、时间
```

口径五项一旦锁定全程不许擅改；变更须重锁并重开版本。**发布目标决定 06 审查方法，时长不自动决定**（影展短片不足 5 分钟也不默认套留存检查）。

**数值口径的提问方式（硬规则）**：目标时长、集数、单集时长等数值项是作者的决定，用 `askUser` 的 `input`/`inputNumber` 字段自由填写；常见区间（如"约 3 分钟""8–10 分钟"）只能进 `placeholder` 作参考提示，**不得做成 radio/select 封闭枚举替作者限定选项**。作者没给数值时问一次，答什么锁什么；答"不知道"才给建议值并标"暂定"。**作者说"你根据故事推荐"时，不得在入口预填时长数字**——先出 01 故事与事件规模，再按密度给时长建议（标暂定），作者确认故事范围后才锁口径；时长永远可重锁（重锁并重开版本）。

## 3 成果状态机与版本

| 状态 | 能否进下游 |
|---|---|
| 未开始（未独立提供） | 否 |
| 草稿待确认 | 否，只能标为试写依据 |
| **已确认-当前** | **是** |
| **外部提供-已确认**（作者原稿/指定资料） | **是** |
| 已过期-禁止使用 | 否，文件保留 |
| 历史已替代 | 否 |
| 缺文件-阻断 | 否，先补文件 |

- `已跳过 / 不适用` 是适用性标记，不占版本号；03、06 典型可跳过。跳过的 03 后来被 06 点中，才首次建 v001。
- 写文件前扫描该目录取下一个三位号；各道独立计号。先落盘、回读验证可读，再在聊天完整展示同一份；保存失败如实说，不拿聊天冒充已保存。
- 成果末尾必带版本卡（模板见各册），写明本版依据（哪份上游哪个确认版）、改动范围、未定项。
- 下游登记依赖必须指向**实际读过的最新确认文件**；不允许登记无上游依据的成果。
- 新版**确认后**，真实依赖旧版的下游才标过期（06 专用态：`已完成-结论` 不等于改稿授权；报告没指最弱一环或没写病灶道号 → `已作废（不合格）` 打回重审）。

## 4 确认、试写与授权

- **试写自由**：草稿、片段、标明的假设都可以直接用于探索，可以跳步、返回、先试后定；不用生产门槛阻断讨论。
- **采用严格**：正式镜头表、资产基准、确认稿、收费生成，只认确认依据。
- 确认是作者意图不是口令：对已展示的完整版本说"确认/可以/就这版"即登记；"还行/继续看看/沉默"不算。未展示的正文不能替作者批准。
- 三类授权分离：内容确认 ≠ 消耗算力授权 ≠ 结果采用。生成前展示具体方案（对象与数量、模型、完整提示词、实际参考与位次、规格、执行次数）；对用户统一称"消耗算力"，查不到写"算力消耗未知"。方案变化（新增数量、换参数、额外重试）需核对原授权是否覆盖。
- 导航 ≠ 确认；修改另存草稿；"修改本阶段"不自动作废任何确认稿。
- 06 报告四种处置如实登记，不规约成统一确认门：**「说对了，改吧」/「说对了但这次不改」/「保留原稿」（不劝第二遍）/「整份不认」（不要求解释）**；支持按病灶编号部分授权（"第 6 场保留，其余改"）。

## 5 病灶回退与熔断

06 报告点中的问题按根因切回唯一一道，未被点到的不动：

| 报告说的问题 | 回哪道 |
|---|---|
| 主角目标不清/变了没推动 | 01 |
| 人物只是功能位/动机不成立/遮名分不出人 | 02 |
| 世界规则与人物选择无关/无代价 | 03 |
| 孤儿场/**关键事件压根没写**/转折错位/时长失衡 | 04 |
| 事件在 04 已写但正文一句带过、没演出来 | 05 |
| 报告只说"整体不错"没指病灶 | 06 重审，01–05 全不动 |

- **04/05 分界口诀**：压根没有→回 04 补；有但没演透→回 05 就地补。判前先查分场那一场写了什么；**一个视线/停顿动作既不足以证明事件成立，也不足以证明事件缺失**。只有外部剧本无从对照时，写「04 或 05（待核实）」且必须写全**缺哪份证据、由哪道补、补完谁复核**，定位未定前严禁动笔。
- 补事件三档最小代价：① 已有场次加一个动作或反应（不增场）→ ② 合并相邻两场 → ③ 才新增一场。
- 外部剧本回退到"未独立提供"的 02/04：先从原稿**提取基线**（02 提动机/语声/关系并标场次出处；04 反推分场只提炼结构）落 v001 交作者核对，再按病灶改出下一版；作者核对时动手改了就留 v001 原件、修改落 v002。严禁凭空编造。
- **双计数器分开记，达 3 熔断停手问作者**：06 重审次数 ×N；「某道+某病灶」被退次数 ×N（病灶键如 `04+缺关键事件`）。只有下一份合格报告正面验证该病灶已解决才归零；报告没覆盖到就不累加不归零。
- 改一句查全身：修订事实先写「旧事实→新事实、范围、不得改动项」入 `filmProject/`，读完整原件查别称、因果后果、空间进出、已写后续集（登记"哥哥在家睡"后后文仍写"从店里隔间出来"就不能交付）；交付完整新版+差异单；作者确认前旧确认稿继续有效。

## 6 剧本接管（B 入口完整流程）

作者已有完整/接近完整标准剧本时用；作者剧本是最高事实来源，接管是补生产资料，不是重跑前序。

1. **原稿留档**：剧本原稿保留原路径/`filmProject/` 登记为 `外部提供-已确认`（引用原文件名，一字不改）；未独立提供的 01–04 记 `未开始（未独立提供）`。
2. **问一次是否先走 06**：选是→先出体检报告再回来；选否→06 记 `已跳过`。
3. **第一轮只做接管检查报告** `filmProject/screenplayIntakeReport-vNNN.md`（同规则取号），完整读剧本后至少写：实际文件名/格式/读取页数与未读页；集数、场景标题、内外景、地点、时间、动作段、对白识别情况；重复场号/缺场号/缺页/乱码；已明确的角色与状态变化、场景、道具、特效、声音；**尚缺的生产资料**（角色状态表、场次制片表、场次时长、资产需求表、表演依据、镜头路线）及为什么 07/08/09 需要它们；世界观是否需要补（现实题材默认不补，复杂规则只提取剧本已明确的，缺口问作者）。标准剧本没有这些表——**不得因为正文出现过角色场景就声称生产资料已存在**。
4. 停下问一句：**「是否保持作者剧本内容不变，只根据剧本补齐后续生产资料？」**
5. 确认后生成 `filmProject/screenplay/productionBreakdown-vNNN.md`（不改作者正文），至少含：
   - **角色与状态表**：一人一个角色 ID，年代/服装/伤势/变身用状态 ID（`C01-A`），不拆成两个角色；
   - **场次制片表**：来源场号、内外景、地点、时间、出场角色及状态、服装、道具、特效、声音、动作风险、连续性要求；
   - **场次时长初估**：按动作与对白估，标注"进 08 后复核"；
   - **资产需求表**：角色状态/场景/道具/特效资产，标注使用场次；
   - **信息缺口**：只问真正影响制作的；
   - **下一步路线**：逐场标「可直接 09 / 先补 07 / 先补 08 / 同缺 07+08」并一句原因，不许笼统写"资料不足"。
   剧本没有规范场号时先问能否加"生产用场号"（只写进派生文件）。
6. 下游按当前目标**最短路由**：缺资产→07 只补当前场次需要的；对白停顿影响时长→08 补节拍；剧本+时长依据+资产+表演齐→09。世界观始终可选。
7. 作者要改剧情→切到 05 修订（或按 06 回退）另存新版；作者剧本更新后只把受影响的生产拆解、资产、表演、镜头、提示词标待复核，不删旧版。

## 7 恢复与交接纪律

- 每完成一个成果、重要确认/修改、阶段交接，更新版本文件与 `projectStatus.md`；上下文被压缩或换会话后，**重新读取所需原件**，不把"上次读过"当永久记忆。
- 超长按章节/集/场分批读，登记覆盖范围（起止锚点+未读范围）；摘要与检查点不能代替原件全文。
- 哈希与文件存在只证明文件没变，不证明内容已读懂；语义核对始终由执行侧完成。
