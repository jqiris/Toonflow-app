# 资产图片生成与工作流执行流程

## 整体链路

从前端点击"生成"到图片落入磁盘的完整链路：

```
用户操作 → 路由 Handler → 项目配置 → AI 供应商 → 工作流执行 → 图片保存
```

---

## 一、路由入口

资产图片生成有两个入口：

### 1.1 单次生成

```
src/routes/assetsGenerate/generateAssets.ts
```

- 接收 `projectId`、`assetsIds`（当前需要生成的资产 ID 列表）
- 从 `o_assets` 表读取资产的 `prompt`（英文提示词）和 `type`（role/scene/tool）
- 从 `o_project` 表读取项目的 `artStyle`、`imageModel`、`videoModel` 等配置
- 逐条调用 AI 生成

### 1.2 批量生成

```
src/routes/assetsGenerate/batchGenerateImageAssets.ts
src/routes/production/assets/batchGenerateAssetsImage.ts
src/routes/production/storyboard/batchGenerateImage.ts
```

- 类似逻辑，但支持一次处理多个资产
- `batchGenerateAssetsImage.ts` 用于分镜阶段批量出图
- `batchGenerateImage.ts` 用于分镜面板生成

### 1.3 提示词润色（前置步骤）

```
src/routes/assetsGenerate/polishAssetsPrompt.ts
src/routes/assetsGenerate/batchPolishAssetsPrompt.ts
```

资产生成前先执行提示词润色。流程：

1. 从 `o_project` 读取 `artStyle`（如 `3D_chinese_traditional`）
2. 调用 `getArtPrompt()` 读取该风格的提示词模板：
   - `data/skills/art_skills/{artStyle}/art_prompt/prefix.md` — 全局前缀约束
   - `data/skills/art_skills/{artStyle}/art_prompt/art_character.md` — 角色模板（type=role 时）
   - `data/skills/art_skills/{artStyle}/art_prompt/art_scene.md` — 场景模板（type=scene 时）
   - `data/skills/art_skills/{artStyle}/art_prompt/art_props.md` — 道具模板（type=tool 时）
3. 将模板合并为系统提示词，把用户的 `describe`（中文描述）和当前 `prompt` 发往 LLM
4. LLM 返回润色后的英文提示词，写回 `o_assets.prompt`

```
o_project 表
```

### 2.2 关键文件

| 路径 | 作用 |
|------|------|
| `src/utils/getArtPrompt.ts` | 根据 `artStyle` 加载对应的 `prefix.md` + `art_{type}.md` 模板 |
| `src/utils/getPrompts.ts` | 通用提示词工具 |
| `src/utils/ai.ts` | `AiImage` / `AiText` / `AiVideo` 核心类 |

## 三、AI 供应商系统

### 3.1 模型字符串解析

`imageModel` 的值格式为 `{vendorId}:{modelType}`，例如 `toonflow:z-image-t2i`。

```
toonflow:z-image-t2i
  └── vendorId: "toonflow"
  └── modelType: "z-image-t2i"
```

### 3.2 供应商文件加载

```
data/vendor/
├── toonflow.ts       → 处理 toonflow:xxx 系列模型
├── atlascloud.ts     → Atlas 云 API
├── klingai.ts        → Kling 视频生成
├── minimax.ts        → MiniMax 视频生成
├── vidu.ts           → Vidu 视频生成
├── openai.ts         → OpenAI 兼容接口（文本模型）
├── deepseek.ts       → DeepSeek（文本模型）
├── volcengine.ts     → 火山引擎
├── grsai.ts          → 硅基流动
├── iflytek.ts        → 讯飞星火
└── null.ts           → 空模板（开发/测试用）
```

加载链路：

```
src/utils/ai.ts
  └── getVendorTemplateFn(model)
        └── vendorId = model.split(':')[0]
        └── vendor.ts: getCode(vendorId)
              └── fs.readFile(`data/vendor/${vendorId}.ts`)
              └── 返回文件内容（字符串）
        └── Sucrase.transform(tsCode) → 转译 TypeScript
        └── new VM 沙箱执行 → 导出 vendor 对象
```

### 3.3 供应商接口约定

每个供应商文件默认导出一个对象，核心方法：

| 方法 | 说明 |
|------|------|
| `text({ messages, tools })` | 文本对话（非图片生成用） |
| `image({ input })` | 图片生成 |
| `video({ input })` | 视频生成 |

## 四、ComfyUI 工作流执行流程

对于使用本地 ComfyUI 的供应商（如 `toonflow.ts`），工作流执行分以下步骤：

### 4.1 工作流定义

工作流 JSON 可以有两种存放方式：

| 方式 | 路径 | 说明 |
|------|------|------|
| 内嵌在 TS 中 | `data/vendor/toonflow.ts` | `COMMON_JSON` / `IMAGE_JSON` 等常量，直接在 TS 文件中 |
| 独立 JSON 文件 | `data/workflows/*.json` | **仅用于参考/开发导出**，运行时不会被加载 |

工作流 JSON 包含完整的 ComfyUI API 格式节点图，会包含一个**占位节点**（通常命名为 `HOLDER` 或 `input`），运行时由代码注入实际的 prompt/seed/分辨率。

### 4.2 执行步骤

```
1. deepCopy(workflowJson)         ← 深拷贝模板，避免污染
2. injectPrompt(workflow, prompt) ← 替换占位节点中的提示词
3. injectSeed(workflow, seed)     ← 注入种子值（0 = 随机）
4. injectResolution(workflow, w, h) ← 注入宽高
5. POST {baseUrl}/prompt          ← 提交到 ComfyUI（body: {prompt, number}）
6. 轮询 GET {baseUrl}/history/{promptId}  ← 等待生成完成
7. GET {baseUrl}/view?filename=xxx&...     ← 下载生成结果
8. convertToBase64(imageBuffer)           ← 转为 base64
9. aiImage.save(ossPath)                  ← 写入磁盘
```

### 4.3 关键参数注入

| 参数 | 来源 | 说明 |
|------|------|------|
| prompt | `o_assets.prompt` | 英文提示词，由 polishAssetsPrompt 阶段生成 |
| seed | runtime 固定为 0 | ComfyUI 中 seed=0 表示完全随机；传 0 不用改 |
| width/height | `o_project` 配置或默认值 | 通常为 512×768 等 |
| baseUrl | `o_vendorConfig` 表 | 用户配置的 ComfyUI 服务地址 |

### 4.4 结果回传

ComfyUI 生成完成后，`/history` 接口返回输出文件列表。代码找到第一个 PNG/JPEG 输出，下载为 Buffer，转 base64。

## 五、远程 API 模式

非 ComfyUI 供应商（Atlas、Kling、MiniMax 等）走远程 API 模式：

1. 构造请求体（prompt / 参数）
2. POST 到云 API
3. 轮询任务状态
4. 下载结果 URL 为 Buffer
5. 转为 base64
6. `aiImage.save()` 保存

## 六、图片保存

### 6.1 保存函数

```typescript
// src/utils/ai.ts
class AiImage {
  async save(path: string) {
    // this.result 为 base64 字符串
    await u.oss.writeFile(path, this.result);
  }
}
```

### 6.2 目标路径

格式：`{projectId}/{type}/{uuid}.{format}`

```
data/oss/
├── 1780761131162/           ← projectId
│   ├── role/               ← type=role
│   │   ├── abc123.jpg
│   │   └── def456.jpg
│   ├── scene/              ← type=scene
│   │   └── ...
│   └── tool/               ← type=tool
│       └── ...
├── smallImage/             ← 自动生成的缩略图镜像
│   └── 1780761131162/role/abc123.jpg
└── artStyle/              ← 美术风格参考图
```

### 6.3 OSS 工具层

```
src/utils/oss.ts
├── OSS 类（单例）
├── rootDir ← getPath("oss") → data/oss/
│
├── writeFile(relPath, data)     ← 写入文件（自动创建目录）
├── getFileUrl(relPath)          ← 获取 HTTP 访问 URL
├── getSmallImageUrl(relPath)     ← 获取缩略图 URL（自动生成 512px）
├── getImageBase64(relPath)      ← 读取为 base64
├── deleteFile(relPath)          ← 删除文件
└── deleteDirectory(relPath)     ← 删除目录（递归）
```

### 6.4 数据库记录

```
o_image 表
├── id          ← 主键
├── assetsId    ← 关联 o_assets.id
├── filePath    ← OSS 相对路径（如 "1780761131162/role/abc.jpg"）
├── type        ← role / scene / tool
├── state       ← 状态（已完成 / 生成中 / 失败）
├── model       ← 使用的模型标识
└── resolution  ← 图片分辨率
```

### 6.5 缩略图

调用 `oss.getSmallImageUrl()` 时按需生成：

1. 检查 `smallImage/{原相对路径}` 是否存在
2. 存在 → 直接返回缩略图 URL
3. 不存在 → 用 `sharp` 库缩放到最长边 512px，写入 `smallImage/` 镜像目录
4. 返回缩略图 URL（生成失败时降级为原图 URL）

## 七、分镜面板生成

分镜流程比资产图片多一个步骤：

```
剧本 → 提取资产 → 生成资产图 → 填入分镜 → 生成分镜面板
```

分镜面板生成：

```
src/routes/production/storyboard/batchGenerateImage.ts
  └── 读取分镜数据（镜头描述、角色位置、场景）
  └── 拼接完整的 panel prompt
  └── 调用 AI 图像生成
  └── 保存到 data/oss/{projectId}/assets/{scriptId}/
```
